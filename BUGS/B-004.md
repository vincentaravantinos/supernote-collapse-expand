# B-004: Name jumps on Expand with no icon move; Recollapse then partially fails

**Status**: Parked — not reliably reproducible. One trace showed the icon's
saved position apparently having drifted (`dx=76, dy=-10`) even though the
user reported moving only the name, which caused the name to be relocated
incorrectly; a careful retry of the same steps on a fresh section behaved
correctly (`dx=0, dy=0`, name untouched). Possibly explained by residual
inconsistency from the same session's earlier partial-Recollapse symptom
rather than a fresh defect — unconfirmed. Diagnostic instrumentation was
removed after cleanup; if this recurs, re-add similar checkpoints (see git
history for this file around the B-004 investigation) before losing the
trace.

## Symptom
Sequence: Collapse a section → Name it → Expand it (no explicit icon move in
between) → the name visibly moves "for no reason" during the Expand.

Then: attempting to Recollapse that same section leaves it half-done — the
frame (`CE_FRAME`) remains on the page, and some other strokes remain too
(not fully absorbed back into the icon's userData / not fully deleted).

These may be one root cause (the Expand-time name reconciliation misfiring
somehow leaves the section in a state that confuses Recollapse's element
matching) or two separate issues — not yet known.

## Hypothesis
Not yet formed with confidence. `expandOne`'s new (B-003 fix) name
reconciliation is gated on `dx !== 0 || dy !== 0` (the icon's own movement
since last save) — the repro has no explicit icon move, so this should be a
no-op. Candidates to check via trace, not yet confirmed:
- `dx`/`dy` may be spuriously nonzero due to a rounding/round-trip
  discrepancy between `section.iconRect` (as saved) and the freshly-read
  icon rect, even though the icon never moved — this would wrongly enter the
  reconciliation block.
- If that block *did* fire, whether `nameFollowDelta`'s bbox comparison
  (`section.nameSyncedRect` vs the freshly-recomputed name bbox) behaved as
  expected — a rounding mismatch there could also produce an unintended
  translate.
- Separately (or consequently): whether the partial-Recollapse symptom stems
  from leftover/duplicate `CE_NAME` or `CE_FRAME` elements after an
  inconsistent Expand, confusing `recollapseOne`'s per-tag element matching.
  `recollapseAction.ts` itself was not touched by the B-003 fix.
