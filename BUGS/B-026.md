# B-026: "Couldn't set the section name" alert although the name was set

**Status**: Fixed

## Symptom

Naming a section (icon + handwriting, confirmed) showed the alert
"Couldn't set the section name — please try again." but the name looked
set on the page.

## Hypothesis

The name insert landed, but the verification read ran on a stale page
snapshot: `reloadFileWithTimeout()` timed out (5 s) right before the
re-read, so `getElements` didn't yet show the new name strokes and the
count check (`existing + new`) came up short. The name path reads back
only once — unlike Expand's insert check, which re-reads up to 3 times
before concluding. On this false negative the code alerts and skips the
delete, so the original loose strokes stay on the page under the new
(tagged) copy: the handwriting is likely doubled.

## Evidence

logcat 2026-09-29 12:01:
- several `reloadFile() timed out after 5000ms` just before,
- `name insert didn't land res={"result":true,"success":true} — nothing deleted`.

## Resolution

Confirmed on-device (logcat 12:09): after a `reloadFile()` timeout, read
attempt 0 found 0/9 name strokes; the retried read found them all and the
name was set without an alert. Fix: the name insert's verification re-reads
up to 3 times (never re-inserts), same as Expand's check. Regression was
introduced in this unreleased cycle, so no CHANGES.md entry.
