# B-017: Moving a section's icon while expanded hangs forever in "Working…"

**Status**: Fixed — `PluginCommAPI.reloadFile()` can hang indefinitely on
this SDK build. Removed entirely from 5 of 6 call sites (`collapseAction.ts`,
`expandAction.ts`, `recollapseAction.ts`, `nameAction.ts`,
`iconMoveRedraw.ts`) after confirming on-device it's no longer needed to
surface a write on this firmware. Kept at the 1 remaining site
(`strokeLinkExpand.ts`, where an immediate same-operation read genuinely
depends on it) but wrapped in a 5s timeout, since it's the same
hang-prone call — a timeout there degrades to an existing, already-safe
failure path (backup preserved, user sees a retry alert) instead of
hanging. Confirmed fixed across Collapse/Expand/Recollapse/Rename/
icon-drag/stroke-link on-device. Reported to Ratta (FEEDBACK.md);
documented in SDK_DOC.md.

## Symptom

After the B-016 SDK fix shipped and the plugin was rebuilt/reinstalled:
Collapse worked, Expand worked. Then dragging an expanded section's icon
(live-redraw path, `iconMoveRedraw.ts`'s `redrawSectionBox`) never
completes — the "Working…" card stays up indefinitely. Reported by the
user during CR-002 Part B re-validation, not yet reproduced with
instrumentation.

## Hypothesis

`redrawSectionBox` awaits a chain of SDK calls (`getCurrentFilePath`,
`getCurrentPageNum`, `saveCurrentNote`, `getElements`, `setLassoBoxState`,
`insertElements`, `deleteElements`, `expandOne`'s own calls, `reloadFile`,
`buildIconCache`) — one of them is likely hanging on the native side
rather than rejecting/resolving. Per this file's own comment, the plugin
host does not pump the JS event loop while idle; if the true cause is a
genuinely stuck native bridge call (not just a slow one), it's plausible
that App.tsx's 7s Cancel-button timer (added for B-008, itself driven by
`setInterval`) never gets to fire either, so the user has no escape hatch
here unlike B-008's original app-switch-away case. Not confirmed — need
to localize which call actually stalls, and separately confirm whether
the Cancel button ever appeared.
