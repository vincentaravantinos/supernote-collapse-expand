# B-023: Expand's insert-verification can pass on stale leftovers, and doesn't clean up partial-failure duplicates

**Status**: Fixed — confirmed via failure injection

## Symptom

After an alert during Expand, the user reports needing 3-4 rounds of
retrying (via Collapse/Expand or Recollapse/Expand cycles) before the
section returns to a normal-looking state. Data is never actually
lost, but recovery takes several manual attempts and, based on the
mechanism found, likely leaves duplicated content along the way until
Recollapse eventually sweeps everything (duplicates included) into one
blob.

## Root Cause (confirmed via code trace)

`expandAction.ts::expandOne`'s insert-verification (the non-stroke-link
path) counts *all* currently-tagged `CE_PART`/`CE_MASK`/`CE_FRAME`
elements for this section's id:

```ts
const landed = check.filter((el) => {
  const ud = readUserData(el);
  return ud != null && (ud.kind === 'part' || ud.kind === 'mask' || ud.kind === 'frame') && ud.id === section.id;
}).length;
insertOk = landed >= batch.length;
```

This doesn't distinguish elements this attempt just inserted from
stale leftovers a *previous*, separately-triggered Expand attempt left
behind — `expandOne` never deletes pre-existing tagged elements for
the section before inserting. Two consequences:

1. A genuinely-failed or short insert can pass verification anyway, if
   stale leftovers from an earlier attempt happen to number
   `>= batch.length` — `insertOk` becomes `true` on a lie, and
   `collapsedElements` gets cleared from `userData` even though the
   *current* content isn't durably on the page.
2. Even when the current insert genuinely succeeds, any leftovers from
   an earlier failed attempt are never cleaned up — they sit there
   as duplicates until an eventual Recollapse serializes everything it
   finds, duplicates included.

## Expected behavior

An Expand attempt should not be able to pass verification based on
content it didn't itself just insert. Retrying after a failure should
converge in one attempt, not several, and should never leave duplicate
content behind.

## Fix Proposal

Before inserting, delete any existing `CE_PART`/`CE_MASK`/`CE_FRAME`
elements already tagged for this section (self-healing cleanup) —
this scopes the verification count to only what *this* attempt
produced, and prevents duplicates from accumulating across retries.
This is safe from a data-loss standpoint: at this point in `expandOne`,
`section.collapsedElements` (the durable backup in `userData`) hasn't
been touched yet — it's only cleared *after* `insertOk` is confirmed —
so the on-page leftovers being deleted are never the sole copy of
anything.

Scope: applies once, before branching into the simple-batch path or
the stroke-link (`rebuildStrokeLinks`) path — both currently lack this
cleanup.

Nominal-case cost: effectively zero extra work for the two current
callers:
- Real Expand (`capturePreserved=true`): already does a full
  `getElements` fetch for `preservedNums` — reuse it for the cleanup
  scan instead of an extra read. The delete call itself stays
  conditional (skipped entirely when there's nothing to clean up,
  matching the existing pattern elsewhere in this codebase).
- Live redraw (`iconMoveRedraw.ts` calling `expandOne` with
  `capturePreserved=false`): its fast path deliberately avoids a
  full-page fetch (~7x cheaper per its own comment) and must stay
  that way. `redrawSectionBox` already does its own full fetch (`all`)
  for unrelated reasons — thread that through as a new optional
  parameter instead of triggering a second, redundant fetch inside
  `expandOne`.

## Next step

Fixed: `expandOne` now cleans up any pre-existing tagged leftovers for
the section before inserting (see DECISIONS.md 2026-09-28). Extracted
the delete-verify-retry loop into a shared `deleteElementsVerified`
helper (also now used by `recollapseAction.ts`, removing a duplicate).
Verified via failure injection — a temporary probe manually inserted
fake leftover elements to simulate a prior failed attempt, and a
normal Expand correctly cleaned them up before inserting fresh
content. Probe removed after confirming.
