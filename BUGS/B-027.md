# B-027: Icon-drag redraw ends in "couldn't complete the expand" alert

**Status**: Fixed

## Symptom

Dragging an expanded section's icon toward the inside of its area: the
redraw ran and ended with an alert (likely "Supernote couldn't complete the
expand — please try again").

## Hypothesis

False negatives from `writeSection`'s verification: `reloadFileWithTimeout()`
keeps timing out, so the `getElement` read-back returns the stale userData,
"didn't stick" → `modifyElements` is re-sent up to 3 times → gives up. In the
redraw, `expandOne` then reports failure although its insert landed, and the
redraw falls back to collapsed with the content still on the page. Same
stale-read class as B-026, but here the WRITE is retried, not just the
read. Possibly related to B-025's duplicated icon (repeated `modifyElements`
on one icon).

## Evidence

logcat 2026-09-29 12:14–12:15: repeated `reloadFile() timed out`; stash
`writeSection attempt 0: userData didn't stick — retrying` (then ok);
`expand: … only 0/6 tagged elements found (read attempt 0) — re-reading`
(then ok); `writeSection attempt 0/1/2 … didn't stick`, `gave up`,
`failed to update section userData after expand`; then another
`writeSection attempt 0 … didn't stick` (the redraw's fallback write).

## Resolution

Confirmed on-device (logcat 13:09–13:10): 10 `reloadFile()` timeouts, no
write re-sent or declared failed. Fix: `writeSection` re-reads up to 3 times
per write attempt before re-sending `modifyElements`. Worth re-checking
B-025 (duplicate icon) against this: repeated `modifyElements` on one icon
was a candidate cause.
