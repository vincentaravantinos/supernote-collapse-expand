# B-032: On a Manta with Chauvet 3.30.45, collapsed sections can't be expanded

**Status**: Parked (waiting for the reporter's log)

## Symptom

Reported on r/Supernote_dev (thread 1u3sa1i, comments phnb1z6 → phuqzw7)
by a Manta user right after updating to Chauvet 3.30.45, with plugin 1.3.0
presumably installed. Collapse works and shows "Working…". Tapping a
collapsed icon with a finger does nothing: no "Working…" card at all.
Lassoing the icon and pressing Collapse / Expand in the lasso toolbar also
does nothing (the button is there). It used to work. Not reproducible on
the developer's A5X (build Chauvet.D102.2610091001).

## Hypothesis

Both failing paths die **before** the "Working…" card, and both involve
reading back an existing icon, which is a TEXT element. Collapse never
reads one back via the lasso and isn't affected.
- Menu: `handleMainAction` → `getCurrentFileContext` / `getLassoElements`
  **hangs**. It can't be throwing, because `handleMainAction` already alerts
  on errors ("An error occurred…") and on busy, and the user saw nothing.
- Tap: `buildIconCache` only registers icons with `el.textBox.textRect`;
  if that's missing or reshaped, `findHit` never matches and the tap is
  silently ignored.
Suspected cause: firmware 3.30.45 changed how elements (text elements in
particular) are marshalled to plugins. `sn-plugin-lib` 0.2.3 (2026-10-12)
documents a coordinate switch from EMR to page pixels ("In sn-plugin-lib
0.1.65 and earlier, they are EMR coordinates"). We build against 0.1.65.
Unconfirmed: no device or logs available.

## Evidence

- Reddit thread above (user's own words).
- `sn-plugin-lib` 0.1.65 → 0.2.3 diff: JS API essentially unchanged
  (comments translated; `modifyPageElements` result typed `number[]`;
  `requestPermission` can now return -1 = cancelled). The substantive change
  is the documented coordinate system for stroke points, five-stars and
  pictures (EMR → Android pixels), which happens on the native/firmware side.

## Instrumentation

- `src/utils/diagLog.ts`: in-memory log (last 300 lines). Every
  `console.error` is mirrored into it.

  (App.tsx), with Clear/Close. The user photographs it.
- Checkpoints: init build, finger motion DOWN/UP coords, tap
  qualification/hit/miss (with icon rects), icon scan (element/text/icon
  counts, first icon textRect vs saved rect, a raw text element if no
  icon is recognised), menu steps (pressed/started/context/lasso result),
  op start/end, dropped-as-busy.
- Experimental: the icon scan falls back to the saved `section.iconRect`
  when `textBox.textRect` is missing.
