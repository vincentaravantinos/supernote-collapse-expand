# B-010: Tapping a section's icon stops expanding it entirely (fixed)

**Status**: Fixed — confirmed by the user on-device (build `r118-stale-cache-retry`).

## Symptom
After the icon (or another element) was repositioned by a plain native drag
(lasso-select-and-move, no plugin button involved), tapping the icon
produced zero effect — no expand, no recollapse, nothing.

## Root Cause
`iconTapToggle.ts`'s `handleTap` trusts a cache hit on the page
(`getCachedIcons(page)` returning non-null) without ever re-validating that
the cached icon *rects* are still correct. The cache is only rebuilt after
the plugin's own operations (Collapse/Expand/Recollapse/Name, live icon-drag)
— a native, button-free drag of the icon is invisible to the plugin and
leaves the cache pointing at the icon's old position indefinitely. Confirmed
via a `[B10-PROBE]` trace: every failed tap showed `cacheHit=true` with the
cached rect sitting ~300-350px away from the actual tap location.

## Fix
On a hit-test miss against the cached icons, `handleTap` now rebuilds the
cache once (a fresh read) and retries before concluding the tap genuinely
isn't on an icon. Costs one extra read only on a miss.

## Instrumentation
A lightweight `[B10-PROBE]` log fires only when this retry actually recovers
a hit, to confirm the fix is being exercised in normal use — much less
verbose than the original per-tap diagnostic logging, which has been
removed now that the mechanism is understood.
