# B-010: Tapping a section's icon stops expanding it entirely

**Status**: Not reproduced since — working normally after a reinstall.
Root cause unconfirmed: the `[B10-PROBE]` instrumentation was only active
*after* the reinstall (which itself restarts the plugin process and could
have cleared whatever bad state existed, independent of cause), so the
original stuck taps were never actually traced. Per the user: keep the
instrumentation in place and observe over the coming days rather than
closing this out or removing the logging yet.

## Symptom
After a Name/Rename action completed normally, repeated single-finger taps
on a section's icon produce zero effect. Raw touch events are logged
(`[B8-PROBE] DOWN`/`UP`) but nothing downstream ever fires — no hit, no busy
rejection, no operation of any kind.

## Hypothesis
Likely a regression from this session's own eager icon-cache rebuild (added
to speed up the tap-response bubble): `buildIconCache` now runs
unconditionally after every operation, replacing the previous
"invalidate-and-rebuild-lazily" behavior. If that rebuild's `getElements`
read ever comes back empty or unsuccessful, the cache is left *populated but
empty* rather than absent — and `getCachedIcons`/`handleTap` only rebuild
when the cache is *missing* (`null`), not when it's empty. An empty-but-warm
cache would make every subsequent tap's hit-test silently find nothing,
indefinitely, until something else (a page change, or another successful
operation) happens to rebuild it correctly.

Neither `buildIconCache` nor `handleTap`'s early-return paths (landscape
check, no page, no hit, busy rejected) log anything today, so this can't be
confirmed from the existing trace — it's a plausible mechanism, not a
verified cause.

## Evidence
One occurrence, from raw touch logs showing taps with no plugin follow-up
at all. Not yet correlated with a confirmed empty-cache state.

## Instrumentation
Adding logging to `buildIconCache` (result count) and to each of
`handleTap`'s silent early-return points, so the next tap attempt reveals
exactly where it's bailing.

## Next step
Ask the user to reproduce (tap the icon again) with the instrumented build,
then read the trace.
