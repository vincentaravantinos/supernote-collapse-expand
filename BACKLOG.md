# Backlog

Open feature requests and deferred items. Worked per the workflows in
`AGENT.md` (features → architect-challenge then implementation). Remove
an item once the user confirms it's done.

1. FEATURE: support **nested sections** — collapsing a region that contains another section's icon (and recollapsing/expanding correctly when sections are nested or overlap). Currently a non-goal (SPEC: "Sections do not nest or overlap"); this item is to lift that restriction.
2. FEATURE (BLOCKED — needs SDK change): make the **menu button label reflect the action that will occur** for the current selection — e.g. "Collapse" / "Expand" / "Recollapse" — instead of the single static "Collapse / Expand" label. Probed 2026-06-11 and found not feasible with the current SDK: re-registering the button only relabels the *next* toolbar (not the one already open), and there is no selection-made / menu-opening event to update before the toolbar renders (see SDK_DOC.md → "Toolbar button labels are fixed for the open toolbar"). Feedback filed in FEEDBACK.md. Revisit if Ratta adds a label-update or selection-changed API.
3. PERF (needs SDK change or native module): on pages dense with handwriting, operations are still several seconds — the read-path cost was optimized (2026-06-11) but the floor is the SDK's per-write file cost (insertElements / modifyElements / deleteElements / saveCurrentNote each rewrite/reprocess the whole page, ~2-3s each regardless of how few elements we touch). Cutting this needs fewer mutation calls (e.g. batching insert+modify, if the SDK allows) or moving the element I/O to a native module that bypasses the JS bridge. Out of scope for v1.
4. FEATURE: **name collapsed sections using handwritten strokes instead of typed text** (supersedes two earlier attempts at named/customized sections: "different kinds of collapsed sections", and a deferred context menu that tried to type a name into a popup). That 2026-06-19 attempt displayed the typed name via a TEXT element's `textContentFull`, which was unreliable across collapsed/expanded states because `modifyElements` doesn't update `textContentFull` — the rename required delete+reinsert, which shifted `numInPage` and interacted badly with SN render order and lasso-containment. Using strokes instead of a typed string sidesteps that bug entirely (it's just ink, not a TEXT element), and also avoids the general brittleness of the text-field approach. Letting the user write whatever title they want also covers the earlier "customize the `+` glyph" request, so that's dropped as a separate item.
   Flow:
   1. User lassoes the content to collapse and presses Collapse as today. **Nothing is deleted yet.** The plugin shows an info message: "Write the title of this section somewhere on the page, lasso it, and press Collapse/Expand again (10s)." The pending content-to-collapse selection is held only in JS memory, not persisted — if the device reboots before a title is supplied, the plugin simply forgets the pending request; since nothing was deleted, no content or state is lost, so this needs no special handling under the SPEC's persistence requirement.
   2. If the user presses Collapse again within 10s with a new lasso, that lasso is taken as the title strokes, and the plugin performs the real collapse: deletes both the original content and the title strokes from the page, and creates the icon.
   3. If the 10s timeout elapses first, the pending request is silently dropped and the user must start over from step 1.
   4. The "+" icon still appears next to the title (up-right of it), same visual role as it has today for anonymous sections.
   5. The title strokes need their own visual marker distinguishing them as a section title rather than ordinary handwriting — candidate: reuse the existing `CE_FRAME` outline mechanism around the title, or an underline beneath it. Not yet decided.

   Open design questions: (a) what should happen if the user does something else — e.g. presses Collapse on unrelated content — while a title is pending, before the 10s elapses; (b) exact `userData` tagging for the title strokes so they're distinguishable from the rest of the section's `CE_PART` content on expand/recollapse (needed so they can be redrawn with their frame/underline marker, and so recollapse can tell them apart from strokes added later).
