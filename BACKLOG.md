# Backlog

Open feature requests and deferred items. Worked per the workflows in
`AGENT.md` (features → architect-challenge then implementation). Remove
an item once the user confirms it's done.

1. FEATURE: support **nested sections** — collapsing a region that contains another section's icon (and recollapsing/expanding correctly when sections are nested or overlap). Currently a non-goal (SPEC: "Sections do not nest or overlap"); this item is to lift that restriction.
2. FEATURE (BLOCKED — needs SDK change): make the **menu button label reflect the action that will occur** for the current selection — e.g. "Collapse" / "Expand" / "Recollapse" — instead of the single static "Collapse / Expand" label. Probed 2026-06-11 and found not feasible with the current SDK: re-registering the button only relabels the *next* toolbar (not the one already open), and there is no selection-made / menu-opening event to update before the toolbar renders (see SDK_DOC.md → "Toolbar button labels are fixed for the open toolbar"). Feedback filed in FEEDBACK.md. Revisit if Ratta adds a label-update or selection-changed API.
3. PERF (needs SDK change or native module): on pages dense with handwriting, operations are still several seconds — the read-path cost was optimized (2026-06-11) but the floor is the SDK's per-write file cost (insertElements / modifyElements / deleteElements / saveCurrentNote each rewrite/reprocess the whole page, ~2-3s each regardless of how few elements we touch). Cutting this needs fewer mutation calls (e.g. batching insert+modify, if the SDK allows) or moving the element I/O to a native module that bypasses the JS bridge. Out of scope for v1.
4. FEATURE-CHANGE: **Name/Rename should not reposition the name strokes.** Shipped 2026-07-12: `nameAction.ts` anchors the name up-right of the icon, translating the selected ink there. User wants the strokes left exactly where written — no anchor/translate at all. Likely a simplification: drop the anchor/`dxPx`/`dyPx`/`emrDelta` computation in `handleNameAction` and just re-tag the selected strokes in place (still needs delete-old+insert-new for the `CE_NAME` tag, per the existing crash-safety pattern — just with a zero-ish delta rather than a computed one).
5. FEATURE-CHANGE: **a section's name should follow an icon moved while expanded only at the next Recollapse, not live.** Shipped 2026-07-12: `iconMoveRedraw.ts`'s live per-drag redraw relocates the name immediately, mirroring how content's mask/frame respond live. User wants this deferred instead, matching how a *collapsed*-icon move is already only reconciled at the section's next Expand (`expandAction.ts`). Move the name-translation logic out of `iconMoveRedraw.ts` into `recollapseAction.ts`, translating by the delta between the section's last-saved `iconRect` and the current one.
6. FEATURE: **give a section's name a visual marker (underline)** distinguishing it from ordinary handwriting sitting near the icon. SPEC.md's Name/Rename operation doesn't define one today. Needs an Architect pass to pick an SDK-supported underline mechanism (e.g. a `GEO` polyline/thin-rectangle under the name's bounding box, similar to how `CE_MASK`/`CE_FRAME` are drawn for an expanded section) and a new `CE_` tag + lifecycle for it (created on Name/Rename, translated alongside the name strokes on any icon move, deleted only when the section or its name is destroyed).
7. FEATURE: **extend the single-finger tap-to-toggle shortcut (see CHANGES.md 1.0.1) to a section's name, not just its icon.** Tapping the name should collapse/expand the section the same way tapping the icon already does. Needs `iconTapToggle.ts`'s hit-testing to also cover the name's on-page bounding box, and likely an extension of `iconPageCache.ts`'s per-page cache (currently icon-only) to also track name rects.
