# CR-010: Self-heal a duplicated section id

**Status:** Done

## Request

BACKLOG.md item 4. A section's whole identity is a single `id`
embedded in its icon's userData, generated once at Collapse. A native
(non-plugin) copy-paste of that icon duplicates the `id` verbatim,
producing two sections that silently share it. User request (kept
deliberately simple): whenever the plugin already has an opportunity to
notice this (an existing scan it's already doing for another reason),
detect two icons sharing the same `id` and self-heal by regenerating
one of them — no dedicated new pass or proactive check.

## Impact analysis

**Low impact — fast-track.** Self-contained: `buildIconCache`
(`src/logic/iconPageCache.ts`) already scans every `CE_PLUG` icon on a
page for tap hit-testing, and runs after every Collapse/Expand/
Recollapse/live-redraw. Detecting a duplicate `id` in that same scan
and regenerating it is one function, no new data model, no new user
flow.

Scoping decision: only self-heal a **collapsed** colliding icon — its
entire identity lives in its own userData, so changing its `id` is
fully safe. An **expanded** colliding section also has `CE_PART`/
`CE_MASK`/`CE_FRAME`/`CE_HANDLE`/`CE_NAME`/`CE_UNDERLINE` elements
tagged with the same id; regenerating just the icon's id would orphan
all of those instead of fixing anything. Left untouched for now — it's
also the less likely real-world case (copy-pasting a small collapsed
icon glyph is natural; copy-pasting a whole expanded section's visible
area is not).

## Next step

Done. Implemented in `buildIconCache` (`src/logic/iconPageCache.ts`):
detects a duplicated id in its existing full-page icon scan and
regenerates it for all but one collapsed colliding icon, gated behind
the existing busy lock (see DECISIONS.md 2026-09-28 for the collapsed-
only scoping rationale). REQ-400 added and reviewed. Confirmed
on-device: a native copy-paste of a collapsed icon self-heals, and both
copies then behave as fully independent sections.
