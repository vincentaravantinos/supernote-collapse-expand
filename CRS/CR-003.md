# CR-003: Audit 1-indexed page/element indices

**Status:** Analyzed

## Request

As of the Chauvet 3.29.43/2.26.40 SDK release, element/page indices
(`numInPage`) and the index parameters of `getElement`,
`getElementNumList`, and `deleteElements` are now consistently
1-indexed (previously the convention differed).

`collapse_expand` calls all three of these directly, across
`collapseAction.ts`, `expandAction.ts`, `recollapseAction.ts`,
`nameAction.ts`, and `iconMoveRedraw.ts`, with page/element indices
sourced from `getCurrentPageNum()`/`getElements()`/`getElementNumList()`
results. Need to enumerate every such call site and confirm/fix against
the new 1-indexed convention.

Source: r/Supernote_dev, "Plugin Preview Build: Chauvet 3.29.43 Beta for
Manta / Nomad and Chauvet 2.26.40 Beta for A5X / A6X" (u/Dunn-sn), API
Changes section.

## Impact analysis

**Low impact — fast-track.** Once call sites are enumerated, the fix
(if needed at each site) is a mechanical indexing adjustment — no new
requirements or design tradeoffs. Unlike Scribble's own CR-003 (which
closed as not-applicable, since Scribble doesn't use any of the named
APIs), `collapse_expand` uses `getElement`, `getElementNumList`, and
`deleteElements` directly, so this needs genuine on-device confirmation
rather than a grep proving non-use — still a single well-understood
class of fix, not a design question.
